Setup

কীভাবে Configure করে?

# pgbouncer.ini
[databases]
mydb = host=127.0.0.1 port=5432 dbname=myapp

[pgbouncer]
pool_mode = transaction # recommended
max_client_conn = 1000 # app থেকে কত নেবে
default_pool_size = 20 # DB-তে কতটা রাখবে
listen_port = 6432

Prisma-তে ব্যবহার

DATABASE_URL="postgresql://user:pass@localhost:6432/mydb?pgbouncer=true"
# ?pgbouncer=true = prepared statements disable (important!)

Transaction Mode — রহিম → করিম → জাবের

র
রহিম connect করে → pool-এ slot পায় → query পাঠায়
✅ রহিম-র transaction শেষ → connection pool-এ ফিরল → free!
ক
করিম রহিমের connection নিল → query করল → আবার pool-এ ফিরল
জ
জাবের করিমের connection নিল → ৫টা connection দিয়ে হাজারো user!

৫টা connection — রহিম, করিম, জাবের, হাচান সবাই served। নতুন connection বানানো হয়নি!

Serverless

Vercel / Lambda-তে বিশেষভাবে দরকার

❌ PgBouncer ছাড়া Serverless

প্রতিটা Lambda function invocation = নতুন DB connection। ১০০০ simultaneous request = ১০০০ connections। PostgreSQL crash করে।

✅ PgBouncer সহ Serverless

১০০০ Lambda function → সবাই PgBouncer-এর pool share করে → DB মাত্র ২০টা connection দেখে → শান্তিতে কাজ করে।

Common ভুল

❌ Prepared Statement ব্যবহার

Transaction mode-এ server-side prepared statements সমস্যা করে। Prisma-তে ?pgbouncer=true দিতে হবে।

❌ pool_size > max_connections

PostgreSQL-এর max_connections-এর বেশি pool_size দিলে connection refused। সবসময় DB limit-এর নিচে রাখো।

⚠️ Long Transaction

Transaction mode-এ দীর্ঘ transaction connection ধরে রাখে। Queue জমে যায়। query_wait_timeout সেট করো।

⚠️ Session Variable

Transaction mode-এ SET LOCAL পরবর্তী user-এ leak হতে পারে। Careful!

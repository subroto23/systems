কেন HTTP যথেষ্ট না?

Realtime-এর জন্য HTTP-র সমস্যা
❌
HTTP Polling — রহিম প্রতি ২ সেকেন্ডে জিজ্ঞেস করছে "নতুন message এসেছে?"

HTTP সমস্যা

  • প্রতিটা request নতুন connection
  • Header বারবার পাঠাতে হয় (1KB+)
  • ১০০০ user = ৫০০ request/sec
  • Server ক্লান্ত, delay বেশি
// HTTP Polling — ভুল পদ্ধতি setInterval(async () => { const res = await fetch('/messages'); // নতুন message নেই? waste। // আছে? তাহলে ঠিকাছে। // কিন্তু ২ সেকেন্ড delay! }, 2000);
✅
WebSocket — একবার connect করো, সারাক্ষণ open থাকে। Server যখন চাইলে push করতে পারে।

WebSocket সুবিধা

  • একটাই persistent connection
  • Header overhead নেই (শুধু data)
  • Server → Client push (real realtime)
  • Latency: ১০০ms → ১ms

SLIDE 03

Connection-এর আগে ৪ Layer Security

যে কেউ connect করতে পারবে না
১

JWT Verify — Handshake-এ token পাঠাতে হবে। Invalid token → connection reject।

২

Rate Limit — এক IP থেকে ৫ সেকেন্ডে ৩টার বেশি connect attempt → block করো।

৩

Enrollment Check — রহিম কি এই class-এ enrolled? না হলে room join করতে পারবে না।

৪

Ban Check — Redis-এ রহিম ban আছে? তাহলে connection-এই reject।

// Socket middleware (runs before connection) io.use(async (socket, next) => { // Layer 1: JWT const token = socket.handshake.auth.token; const user = jwt.verify(token, SECRET); // Layer 2: Rate limit (Redis) const key = `socket-connect:${socket.handshake.address}`; const count = await redis.incr(key); await redis.expire(key, 5); if (count > 3) return next(new Error('Too many connections')); // Layer 3: Enrollment (done in join-class event) // Layer 4: Ban check const banned = await redis.get(`banned:${user.id}`); if (banned) return next(new Error('Banned')); socket.user = user; next(); });
SLIDE 04

Viewer Count Architecture

Live class-এ কতজন আছে — realtime

কীভাবে count রাখি?

  • Redis SET: viewers:class-101 = {রহিম, করিম, জাবের}
  • Join → SADD, Leave/Disconnect → SREM
  • Count = SCARD (set size)
  • Multiple server-এও accurate
socket.on('join-class', async (classId) => { const roomKey = `viewers:${classId}`; await redis.sadd(roomKey, socket.user.id); const count = await redis.scard(roomKey); io.to(`class:${classId}`).emit('viewer-count', count); });

Disconnect হলে কী হয়?

  • socket.on('disconnect') ট্রিগার হয়
  • SREM দিয়ে ঐ user-কে সেট থেকে বাদ দেওয়া হয়
  • নতুন count আবার সবাইকে broadcast করা হয়
socket.on('disconnect', async () => { await redis.srem(roomKey, socket.user.id); const count = await redis.scard(roomKey); io.to(`class:${classId}`).emit('viewer-count', count); });
💡
একটা সাধারণ in-memory Map ব্যবহার করলে multiple server-এ count ভুল হতো — প্রতিটা server নিজের মতো count রাখত। Redis SET সব server-এর জন্য একই shared state রাখে বলেই count সবসময় সঠিক থাকে।
